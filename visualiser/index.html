What happens when you run run_defense_comparison.sh

Three machines: your host (this repo), the sender VM (192.168.150.10, floods + makes HTTP requests) and the receiver VM (192.168.150.20, runs Nginx). Below is the exact sequence, with real numbers from the current script.

2One trial, step by step

host (your laptop) sender VM (.10) receiver VM (.20) both / network
No tcpdump here. tcpdump only shows up in notes/watching-packets-with-tcpdump.md as a separate manual exercise you run yourself in a third terminal. The automated script never starts it — the only receiver-side observers are server.monitor (polling, every 0.1s) and two nstat -az snapshots (before/after).

3Full run: 6 trials, rotated order

2 trials × 3 conditions = 6 trial runs. The condition order rotates each trial so time-of-run bias (VM warm-up, jitter) can't favor one condition.

Before all of this: the script wipes and re-copies client/ to the sender and server/ to the receiver over scp, so every run tests the code currently on your host, not a stale VM copy.

After all 6 trials: scripts/summarize_comparison.py reads comparison.csv and writes RESULT.txt. Raw per-trial evidence moves into details/. On exit (normal or Ctrl+C), the script restores the receiver's original tcp_syncookies / tcp_max_syn_backlog and reloads nginx again so the box is left exactly as it was found.
